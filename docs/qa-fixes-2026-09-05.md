# Linux frontend fixes and verification — 2026-09-05

## Result

The screenshot-error abort is fixed, and the file-list sorting/refresh hot path is substantially faster. The [original QA report](qa-2026-09-05.md) is the pre-fix baseline.

- Regular suite: **146 passed**, 4 graphical diagnostics and 1 subprocess helper excluded from the default run.
- Explicit graphical diagnostics: **5 passed, 0 failed**. The argument test overlaps the regular suite, giving **150 unique passing tests** in combination. Helper processes are not counted separately.
- Real GTK file/sidebar checks and the opt-in stress assertions passed.
- Strict Clippy, formatting, whitespace checks, and CLI-only compilation passed.
- Tests used isolated temporary/frontend-development data and local test servers. No production Folder, remote VPS, bearer token, or real wallpaper command was used.

The first sandboxed regular run was blocked from creating a Unix socket (`Operation not permitted`). The complete suite was rerun with permission for local sockets and passed; the restriction was not hidden or treated as a product failure.

## Changes

### Screenshot failure

`capture_widget` now unrealizes the renderer before the fallible PNG write. The application propagates capture errors to a normal exit with code **1**, instead of disposing a realized renderer and aborting. Successful capture exits with code **0**.

The regression test checks a missing parent directory, an existing directory as the output target, and a subsequent valid PNG. It requires exact exit codes (a signal cannot pass), checks the error message and PNG signature, and verifies the target directory remains present.

### File-list responsiveness

- Folder snapshots share history through `Arc<FileHistory>` instead of cloning every delivery on view changes.
- Filename case folding, MIME categories, and ID positions are prepared once when loading on the worker. File settlement updates one indexed record; arbitrary bulk mutations invalidate the cache.
- Filtering borrows history and cached keys. Partial selection orders only the requested prefix; only displayed records are cloned for rows. Matching totals still cover all history.
- Identical phase events return without requesting a render. Actual phase changes replace only changed visible rows; unchanged rows retain their widgets.
- Clearing the selected Folder clears the rendered-row cache, so restoring a Folder cannot leave an empty list with stale cache entries.

New model regressions compare paginated output against an independent full-sort oracle across six directions, four status filters, type filters, Unicode queries, duplicate IDs, and six page limits (including zero and all records). Additional checks cover index updates/invalidation and copy-on-write snapshot isolation. GTK assertions verify repeat-render widget identity, empty-view restoration, and one-row-only replacement on a real phase change, alongside existing sorting, filtering, pagination, Folder switching, and active-first behavior.

## Performance

Same local machine/toolchain as the baseline: i7-13700H, 20 logical CPUs, GTK 4.22.4, libadwaita 1.9.1, Rust 1.98.0. Builds use one Cargo job. These are **debug-build synchronous handler/model/widget costs**, not end-to-end frame latency, release budgets, or hardware-independent guarantees. Normal operations have one warm-up and five measured samples; the table gives medians. Synthetic records contain shuffled names, sizes, dates, and English/Chinese filenames.

| Records | Repeat same sort, before → after | Actual direction switch, after | Search miss, before → after | Actual phase change, after |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 11.46 → 0.21 ms | 8.16 ms | 1.37 → 0.10 ms | 0.36 ms |
| 10,000 | 54.18 → 1.35 ms | 9.62 ms | 15.33 → 0.95 ms | 1.53 ms |
| 50,000 | 275.08 → 6.95 ms | 14.93 ms | 81.90 → 4.66 ms | 7.07 ms |

Repeated selection benefits from unchanged-row reuse; it must not be described as the cost of rebuilding a differently ordered list. The newly added actual-direction and actual-phase measurements exercise real changes, not no-ops. The baseline did not separately measure those operations at every size.

- **100 actual alternating sorts at 10,000 records:** median **54.12 → 9.41 ms**, maximum **57.63 → 9.80 ms**. This is the directly comparable direction-switch test. RSS stayed at 203,004 KiB during the new sequence.
- **32 batches of 64 identical phase events at 10,000 records:** median **54.34 → 0.038 ms**, maximum **0.045 ms** after the fix. This measures duplicate suppression, not unique file arrivals or changing phases.
- RSS at the 50,000-record GTK sort stage: **301.6 → 231.2 MiB**. After restoring the original fixture: **219.7 MiB**, versus **183.6 MiB** before stress. RSS includes allocator/GTK retention; this does not prove leak freedom.
- An eight-second idle sample after settling: **182.0 MiB**, no measurable CPU ticks in that sample. Short idle samples are coarse observations, not a zero-CPU guarantee.
- Sidebar rendering is essentially unchanged: **4.45 ms / 100 Folders**, **45.86 ms / 1,000 Folders**. Sidebar virtualization remains outside this fix.
- The diagnostic helper that requests and clones the *entire* sorted history is not the paginated UI path. At 50,000 records it measured **130.49 ms** for time and **132.83 ms** for name sorting, versus **113.05 / 253.59 ms** before. Full time-sort setup is slightly slower; the fix does not claim every full-history operation improved.

## Recovery and input guards

Reran all four real receiver `SIGKILL` scenarios (partial download, durable content before ACK, source ACK before local reconciliation, wallpaper `Running` before launch), four desktop-startup kill timings, corrupted Folder config isolation, and the screenshot error/success sequence. All passed. Wallpaper recovery uses the harmless `/bin/true` hook.

Invalid CLI combinations, invalid UI action targets, stale selection indices, duplicate tasks, malformed/oversized state, permissions, symlinked locks, and existing transfer/hash/retry/tus/non-image full-chain checks passed. The full-sort oracle and GTK checks guard against performance changes producing stale or incorrectly ordered results.

## Reproduce and limits

```bash
CARGO_BUILD_JOBS=1 cargo test --locked --features desktop --all-targets
CARGO_BUILD_JOBS=1 cargo clippy --locked --all-targets --features desktop -- -D warnings
CARGO_BUILD_JOBS=1 cargo check --locked --no-default-features
cargo fmt --all -- --check
git diff --check

# Requires a graphical session; uses isolated child instances.
ulimit -c 0
CARGO_BUILD_JOBS=1 cargo test --locked --features desktop \
  --test desktop_resilience -- --include-ignored --nocapture --test-threads=1
MIRELAY_DESKTOP_STRESS=1 CARGO_BUILD_JOBS=1 \
  ./dev/frontend/run.sh --workspace qa-final-20260905 --file-smoke-test
```

Not certified here: release performance, cold-load latency, subsequent paint/compositor frames, many simultaneously active transfers, long-duration leaks/soak, OOM, actual disk exhaustion, power loss, remote-server load, or screen-reader behavior. Large pages requested through repeated Show More still require proportionally more widgets; this is paging, not full list virtualization.
